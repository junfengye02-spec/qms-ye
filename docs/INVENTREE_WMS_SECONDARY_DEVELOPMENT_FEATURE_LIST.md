# InvenTree WMS 二次开发功能清单

> 盘点日期：2026-09-03  
> 基线：InvenTree 1.5.1（commit `84052e1`）  
> 盘点范围：`InvenTree/` 二开源码与 `inventree-deploy/` 当前运行环境

## 1. 当前结论

本项目当前有效的二开主体，是基于 InvenTree 1.5.1 实现的成品仓扫码 WMS。核心能力已经从最初的“单一扫码入库”，扩展为“扫码入库 + 扫码出库 + 整单审批 + 出库冻结 + 审计追溯 + IPN 标签 + 企业微信通知”。

当前运行环境的核对结果：

| 核对项 | 当前状态 |
| --- | --- |
| 二开 Web、后台任务、PostgreSQL、Redis、Caddy | 已部署并运行 |
| 扫码审批开关 | 已启用 |
| 手机摄像头扫码开关 | 已启用 |
| 审批草稿超时 | 30 分钟 |
| 待审批超时 | 1,440 分钟（24 小时） |
| 单个申请最大扫码明细 | 100 行 |
| 扫码业务记录 | 已有 36 条实际数据 |
| 审批申请 | 已有 11 条实际数据 |
| 商品 IPN 标签模板 | Part、StockItem 各 1 个，共 2 个 |
| 企业微信群机器人 | 功能已实现，当前未配置 Webhook，尚未启用 |

## 2. 业务功能清单

### 2.1 扫码作业

| 编号 | 功能 | 功能说明 | 当前状态 |
| --- | --- | --- | --- |
| SCAN-01 | 统一扫码作业入口 | 在主导航增加“扫码作业”，同一工作台提供入库、出库、当前库存、我的申请、待我审批和操作记录。 | 已部署启用 |
| SCAN-02 | 扫码入库 | 选择或扫描目标库位后，扫描商品码或库存项码，审批关闭时直接增加库存，审批开启时加入待入库申请。 | 已部署启用；当前采用审批模式 |
| SCAN-03 | 扫码出库 | 选择或扫描来源库位后，扫描商品码或库存项码，审批关闭时直接扣减可用库存，审批开启时先冻结库存并加入出库申请。 | 已部署启用；当前采用审批模式 |
| SCAN-04 | 多种条码识别 | 支持商品 IPN、InvenTree 物料码 `INV-PA#`、库存项码 `INV-SI#`，并兼容已绑定的历史外部条码。 | 已部署启用 |
| SCAN-05 | 库位码识别 | 支持扫描 `INV-SL#` 或已关联的库位条码，设置本次入库目标库位或出库来源库位。 | 已部署启用 |
| SCAN-06 | 扫码数量设置 | 每次扫码默认数量为 1，也可输入最多 5 位小数的正数量。 | 已部署启用 |
| SCAN-07 | 扫码枪输入 | 支持 USB HID 扫码枪以键盘输入方式录入，按 Enter 自动提交，并在处理后恢复输入焦点。 | 已部署启用 |
| SCAN-08 | 手机摄像头扫码 | 扫码页可调用浏览器摄像头识别二维码，并修复摄像头组件卸载、停止与重复识别问题。 | 已部署启用 |
| SCAN-09 | 入库未知商品快速建档 | 未知 IPN 入库时弹出商品名称填写框；审批模式下先保存建档快照，审批通过后再原子创建 Part、库存项并入库，不产生半成品数据。 | 已部署启用 |
| SCAN-10 | 库存项智能选择 | 同一商品在指定库位只有一个兼容库存项时自动使用；存在多批次或多上下文时要求人工选择，入库也可明确新建库存项，不按主键猜测批次。 | 已部署启用 |
| SCAN-11 | 库存上下文支持 | 后端支持批次、状态、包装、供应商物料、有效期和指定库存项等上下文，并把会产生副作用的字段纳入幂等校验。 | 已实现 |
| SCAN-12 | 序列号库存保护 | V1 不允许对序列号库存项做直接扫码增减，要求改走原生采购接收、销售发货或序列号状态流程。 | 已部署启用 |
| SCAN-13 | 入出库模式防误操作 | 入库和出库使用不同颜色及明确文案；切换模式或库位时提示保留/取消现有草稿，避免在错误模式连续扫描。 | 已部署启用 |

### 2.2 申请、审批与库存冻结

| 编号 | 功能 | 功能说明 | 当前状态 |
| --- | --- | --- | --- |
| APR-01 | 服务端审批申请单 | 第一次扫码时自动建立服务端草稿，支持一张申请连续加入多条物理扫码记录，并生成唯一申请编号。 | 已部署启用 |
| APR-02 | 入库待处理 | 入库审批通过前只保存待入库明细，不创建新商品、不创建库存项、不改变实物库存。 | 已部署启用 |
| APR-03 | 出库库存冻结 | 出库扫码被接受后立即冻结对应可用库存，避免同一库存被其他申请或原生业务重复占用。 | 已部署启用 |
| APR-04 | 整单原子审批 | 审批通过时重新校验商品、条码、库存项、库位、批次、权限和可用量；整单全部成功才落账，任何一行失败则整单不部分执行。 | 已部署启用 |
| APR-05 | 完整申请生命周期 | 支持草稿、提交审批、通过、驳回、撤销、移除草稿明细和自动超时；驳回必须填写原因，已提交申请撤销也必须填写原因。 | 已部署启用 |
| APR-06 | 我的申请 | 操作员可按状态查看本人申请、行数、数量、库位、审批路径、剩余时间和处理结果。 | 已部署启用 |
| APR-07 | 待我审批 | 审批人可查看路由给自己的待审批申请，打开明细后通过或驳回。 | 已部署启用 |
| APR-08 | 库位审批负责人 | 每个库位可配置审批 Owner，Owner 可为用户或用户组；子库位未配置时向父级寻找最近的有效审批负责人。 | 已部署启用 |
| APR-09 | 申请人与审批人分离 | 禁止申请人自审；审批人必须处于启用状态、属于固定审批 Owner，并拥有专用审批权限。 | 已部署启用 |
| APR-10 | 审批快照与时间线 | 保存申请人、审批 Owner、库位路径、提交时间、审批人、审批时间、决定备注、撤销人和撤销时间等长期审计信息。 | 已部署启用 |
| APR-11 | 自动超时释放 | 后台任务每分钟扫描到期草稿和待审批单，自动置为超时并释放出库冻结。 | 已部署启用 |
| APR-12 | 审批参数配置 | 系统设置中可控制审批开关、草稿时限、待审批时限和单据最大行数；存在活动冻结时禁止直接关闭审批开关。 | 已部署启用 |

### 2.3 库存安全与数量口径

| 编号 | 功能 | 功能说明 | 当前状态 |
| --- | --- | --- | --- |
| INV-01 | 实物/冻结/可用三种数量 | 库存接口和页面增加冻结数量、可用数量；可用数量按“实物数量－原生业务占用－扫码冻结”计算。 | 已部署启用 |
| INV-02 | 原生业务联动保护 | 盘点、扣减、拆分、移动、合并、生产领料、销售发货和调拨等原生操作均校验扫码冻结，防止绕过审批消耗已冻结库存。 | 已实现并接入核心流程 |
| INV-03 | 原生库存总账复用 | 扫码实际入出库继续调用 InvenTree 原生 `add_stock()` / `take_stock()`，并生成 `StockItemTracking`，不维护第二套库存余额。 | 已部署启用 |
| INV-04 | 数据库并发保护 | 对 Part、StockItem 和条码命名空间按固定顺序加锁，库存加减使用数据库最新数量，降低并发扫码、建档和扣库存造成的重复或超卖风险。 | 已实现 |
| INV-05 | 请求幂等 | 每次物理扫码使用唯一 `client_event_id`；同一请求的网络重试返回原结果且不重复变更库存，同 UUID 携带不同内容会返回冲突。 | 已部署启用 |
| INV-06 | IPN 唯一性 | Part IPN 保存前去除首尾空格，并通过大小写不敏感哈希实现全公司唯一。 | 已部署启用 |
| INV-07 | 条码冲突保护 | Part 外部条码唯一；给其他对象绑定条码时会检查是否与现有商品 IPN 冲突，避免同一码解析到不同对象。 | 已部署启用 |

## 4. 当前不包含的功能

以下内容未实现或明确不属于本期二开，不能在对外功能说明中写成“已有”：

- 多级、会签或按金额/数量动态变化的复杂审批流；当前是一张申请对应一个审批 Owner。
- 自动创建销售订单、采购订单或正式发货单；当前扫码出库是直接库存出库，经审批后扣减库存。
- 序列号库存的直接扫码入库/出库。
- ERP、MES、财务系统的正式同步接口。
- 离线扫码、断网后本地排队同步、原生手机 App。
- 企业微信应用审批、回调或通讯录组织架构；当前仅支持群机器人主动通知。
- 用商品 IPN 标签替代 `INV-SI#` 库存项码；两者语义仍严格区分。
