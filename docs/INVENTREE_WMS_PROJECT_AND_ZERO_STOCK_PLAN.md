# 项目名称统一与零库存提示执行计划

- 日期：2026-09-09
- 状态：已实施，验收结果见 [项目与零库存验收记录](INVENTREE_WMS_PROJECT_AND_ZERO_STOCK_ACCEPTANCE.md)
- 初始交付为计划文档；2026-09-09 根据用户“执行计划”指令实施代码及独立预览验收。无新增数据库迁移，未发布正式环境。
- 目标：统一“项目”的业务名称，解释候选项的来源，明确展示当前范围内无库存、无可用库存和出库归零的状态。

## 1. 已确认需求

### 1.1 “项目号”统一改为“项目”

页面标签、列表列名、筛选名称、校验提示、导入导出表头统一使用“项目”。数据库继续使用 `StockItem.batch` 字符串字段，长度限制仍为100个字符，不改字段名、不迁移数据、不改已有项目值。

库存明细导出和库存导入模板继续共用同一份字段定义，只修改其中的中文列名。不增加另一套导入适配逻辑。更新测试文件和使用说明，历史验收报告保留原记录；旧文件使用时将表头“项目号”改为“项目”，无需修改数据内容。

### 1.2 项目候选来自已保存库存

不新增项目表或独立的项目创建页面。入库时允许选择已有项目，也允许直接输入新名称。

- 输入名称本身不保存数据；关闭表单不会创建项目。
- 普通入库成功落账，或库存初始化导入成功后，名称随库存记录保存。
- 如启用了审批，新名称需在审批通过、库存正式落账后才成为库存来源的候选项；草稿或待审不应被描述为已经创建库存项目。
- 入库候选继续从当前有效库存记录中的非空项目值去重获取，不为已无库存记录的项目建立独立历史目录。
- 出库项目按选定设备和实际库位获取，不能混入其他设备、其他库位的项目。

入库字段旁增加简短说明：

> 可选择已有项目或直接输入新名称；入库成功后保存，需审批时以审批通过为准。

### 1.3 零库存与无可用库存提示

选择库位并输入有效设备码后，应主动展示库存状态，不能只留下没有解释的空项目下拉框。

| 场景 | 提示与行为 |
|---|---|
| 当前实际库位该设备所有项目的库存总数为0，或没有库存记录 | “当前库位该设备暂无库存，无法出库。”；禁止出库 |
| 选定项目后，该设备在该实际库位的库存总数为0 | “当前项目在此库位暂无该设备库存，无法出库。”；禁止出库 |
| 库存大于0，但全部冻结或业务占用，可用数量为0 | “当前无可用库存，库存已冻结或占用。”；禁止出库 |
| 可用数量大于0 | 展示当前库存和可用数量，按原出库规则操作 |
| 出库成功，选定设备＋项目＋实际库位的剩余库存为0 | “出库成功，当前库存已为0。”；保留成功记录，并刷新库存状态及候选项 |
| 存在多个项目但尚未选择项目 | 提示“请选择项目查看可用库存”；汇总数量需明确是当前库位该设备的所有项目合计 |

“库存为0”和“可用库存为0”必须区分。查询失败、设备码无法识别、尚未填写条件也必须分别处理，不能误报为无库存。

## 2. 当前实现依据

- `InvenTree/src/backend/InvenTree/stock/models.py`：项目实际存储于 `StockItem.batch`，为 `CharField(max_length=100)`。
- `InvenTree/src/backend/InvenTree/stock/wms.py`：`WmsOptions` 从库存记录提取去重项目；出库选项目前通过 `quantity__gt=0` 过滤，因此零库存时可能只剩空下拉框。`COUNT_COLUMNS` 同时服务库存导入模板和库存明细导出。
- `InvenTree/src/frontend/src/pages/stock/ScanWorkPanel.tsx`：入库使用可输入的项目控件，出库使用选择控件，现有项目请求随设备码、库位、出入库模式变化。
- `InvenTree/src/frontend/src/pages/stock/WmsInventoryPanel.tsx`：已有库存不足的中文错误提示，但尚不足以解释提交前的零库存状态。
- `InvenTree/src/frontend/src/pages/stock/ScanStockTypes.ts`：已有库存项变动后数量和设备总量字段，不能直接将单库存项归零或设备全局总量用于当前项目＋实际库位的归零判断。

## 3. 执行步骤

### 第一步：统一业务名称和文件表头

1. 检索WMS业务路径中的“项目号”，列出页面、筛选、弹窗、错误提示及导入导出涉及的位置。
2. 将用户可见名称改为“项目”，保留内部API字段 `batch` 和数据库字段。
3. 修改共享表头定义，让库存明细导出、库存导入模板均输出“项目”，列名和顺序仍完全一致。
4. 更新设备汇总、期间出入库记录中的相应中文标签及相关翻译资源。
5. 更新有效测试样例和操作说明，不将已有项目字符串的内容批量替换。

验收：界面及新生成的文件不再显示业务标签“项目号”；导出文件可直接导入，原样导入的数量差额为0。

### 第二步：补充项目输入说明与候选刷新

1. 在入库项目输入框增加保存时机说明，不引入额外创建按钮。
2. 排除空值及空字符串候选，沿用现有名称保存与去重规则，不自行引入大小写合并等新规则。
3. 入库成功后刷新项目候选，确保新名称无需整页刷新即可出现。
4. 导入成功和审批正式落账后，使相关候选查询失效并重新获取。
5. 出库更换设备、实际库位或模式时清除不再适用的项目选择，避免沿用上一组条件。

验收：只输入后关闭不会产生新候选；成功入库后出现新候选；其他设备或库位的出库项目不会混入。

### 第三步：提供准确的库存状态

优先扩展现有选项查询或复用现有库存查询及数量计算，避免新增平行业务计算链路。

1. 在过滤出库可选项目之前，取得设备在当前实际库位的库存状态，包括保留的零库存记录。
2. 返回当前查询范围的库存数量、冻结数量、业务占用数量和可用数量。可用数量沿用现有后端规则，不在前端重新推算。
3. 已选择项目时限定该项目；未选择时标明所有项目合计。实际库位必须精确匹配，不包含子库位。
4. 对设备码、设备条码和库存项码沿用现有解析与校验逻辑。库存项码还需校验其设备、项目及库位归属，不得借助该码绕过所选范围。
5. 将设备无法识别、无库存、无可用库存及查询异常区分为可供前端展示的状态。
6. 保留原有读权限校验，不向无权限用户提供额外库存信息。

数量应采用后端Decimal结果传递和比较，避免浮点误差导致归零误判。

### 第四步：接入提交前提示和成功归零提示

1. 条件完整后查询；加载中显示正在查询，失败时显示查询失败并提供重试方式。
2. 展示第三节约定的状态文案及当前库存/可用数量，无库存或无可用库存时禁用出库按钮。
3. 条件变化后不展示上一条件的提示；快速切换设备、项目、库位时，旧请求结果不得覆盖当前状态。
4. 出库成功后按本次已提交的设备、项目、实际库位重新查询剩余库存，不能依赖已清空的输入框，也不能仅依据某一条库存项的数量判断整个组合归零。
5. 仅在出库成功且范围内实际库存归零时展示“出库成功，当前库存已为0”。如果只是查询时已经为0，不使用“出库成功”文案。
6. 如提交的是待审批申请，只提示申请/冻结状态；只有审批实际落账后才能显示成功归零。
7. 提交前的提示仅辅助操作，最终仍由后端事务内重新校验可用库存，保留并发防超扣、冻结保护和重试防重复处理机制。

## 4. 预计改动范围

| 模块 | 计划改动 |
|---|---|
| `stock/wms.py` | 中文共享表头、项目选项及库存状态查询，复用现有数量计算 |
| `stock/services.py` | 优先保持不动；只有现有返回结果不足以准确表达落账范围时才补充结果，不重写出库服务 |
| `ScanWorkPanel.tsx` | “项目”标签、输入说明、状态提示、候选刷新及归零提示 |
| `ScanStockTypes.ts` | 必要的库存状态响应类型 |
| `WmsInventoryPanel.tsx` / `WmsNativeTools.tsx` / `StockItemTable.tsx` | 业务名称、筛选及成功操作后的查询刷新 |
| 翻译资源及相关测试 | 文案编译、接口与界面回归 |

最终文件范围以代码检索结果为准。无需新增数据库表、迁移或独立项目管理功能。

## 5. 验收用例

| 编号 | 操作 | 预期 |
|---|---|---|
| P01 | 浏览入出库、库存列表、筛选及记录 | 业务标签统一为“项目” |
| P02 | 下载库存模板与导出当前库存 | 表头和顺序完全相同，均使用“项目” |
| P03 | 将新导出文件原样上传并提交 | 正常预览，差额为0，库存数量不变 |
| P04 | 输入新项目后关闭表单 | 不保存项目，不增加库存记录 |
| P05 | 新项目普通入库成功 | 库存保存，新名称进入候选 |
| P06 | 通过初始化导入新项目 | 提交成功后新名称进入候选 |
| P07 | 相同项目名称出现在多条库存中 | 候选列表不重复 |
| P08 | 输入非法设备码或查询失败 | 显示对应错误，不提示“暂无库存” |
| Z01 | 设备在所选实际库位没有库存 | 明确提示无库存并禁止出库 |
| Z02 | 该设备只有其他库位或子库位有库存 | 所选实际库位仍提示无库存 |
| Z03 | 当前项目库存为0，其他项目有库存 | 当前项目提示无库存，其他项目不影响判断 |
| Z04 | 实际库存为10，冻结/占用全部10 | 提示无可用库存，不提示实际库存为0 |
| Z05 | 实际库存10，可用6，申请出库7 | 后端拒绝超量，不错误扣减 |
| Z06 | 实际库存1，成功出库1 | 提示出库成功且库存为0，成功记录保留 |
| Z07 | 同组合存在多条库存，其中一条扣完，另一条仍有库存 | 不误报整个组合为0 |
| Z08 | 成功出库后实际库存仍大于0，但可用为0 | 显示实际数量及无可用库存状态 |
| Z09 | 快速切换设备、项目、库位 | 提示始终对应最新条件，不残留旧项目 |
| Z10 | 两个操作人并发出库 | 后端按最新可用库存校验，不超扣 |
| A01 | 启用审批后创建草稿、提交申请 | 不提前显示正式入库成功或出库归零 |
| A02 | 审批通过后库存实际归零 | 刷新后的状态准确体现无库存 |
| A03 | 审批拒绝、取消或释放冻结 | 可用数量及提示随刷新恢复 |

## 6. 验证与交付顺序

1. 先为新增状态及导入导出表头编写有针对性的回归测试，再实现改动。
2. 在独立测试数据库运行库存与审批相关测试，后端使用 `--keepdb`。
3. 完成前端类型检查、相关代码检查、翻译编译和生产构建。
4. 在本机独立预览实例执行上述人工用例，使用专门的测试项目、设备和库位，不混用真实业务数据。
5. 交付更新后的预览、表头已更新的测试文件及验收记录，说明测试数据和未覆盖项。

本计划不包含提交、发布正式环境或清理既有数据。执行时保持现有出入库和审批业务规则。
