# 合同、质保及完整标签使用与维护说明

更新日期：2026-10-10。代码目录：`InvenTree/`。本说明对应本次实现，实际发布及真实打印机验收另行记录。

## 操作员入库

1. 日常打开“出入库申请”直接扫码，已有设备可扫描设备编号、库存项码或完整标签，无需打开填单窗口。新到货需要准备标签时，从库存列表点击“入库填单与打印”，选择已有项目、合同和入库库位；没有对应项目时先点击“新建项目”。
2. 按设备编号或名称搜索管理员已建立的设备资料，填写准备数量并添加明细。无需扫描屏幕上的基本码。
3. 验收日期就是合同起始时间，质保月数统一在合同维护。入库时可以不填写验收日期，入库后在后台补填或更新；不再提供明细单独覆盖验收或质保。
4. 保存后查看明细和标签预览，勾选设备并为每条设备分别填写“打印数量”，默认各 1 张。例如设备 A 设 2 张、设备 B 设 5 张，会生成 7 页标签。打开打印窗口后仍可分别调整数量，再选择队列打印或下载 PDF；单条补打同样支持独立数量。每条数量必须为正整数，整批不能超过配置上限（默认 500 张）。准备数量、实际申请数量和打印数量相互独立，保存与打印均不增加库存。失败重试保留原设备和原数量，修改数量后应新建任务。
5. 贴标后可直接打开“出入库申请”，或从已保存的入库单点击“转到实物扫码核对”，用扫码枪输入实物完整码。系统自动填入只读的设备ID、设备名称、项目和合同号核对栏，并显示质保信息；入库带出准备库位及准备数量。扫码枪回车先填充，核对后点击“加入待入库”，不会仅因扫码回车就创建申请。摄像头入口暂时注释停用，保留代码供以后恢复。
6. 核对实际数量；与准备数量不同时必须勾选明确确认。准备 10 台、实际到货 8 台时，审批只申请 8 台，剩余 2 台以后另建明细。
7. 加入草稿后提交原有审批。从指定入库单进入时，部分提交会列出未核对明细，未核对行不会自动提交。记录可从库存页“入库填单与打印 → 已保存的入库单”继续处理。“新建入库单”会清空当前未保存表单；填写完成并点击“保存并准备打印”后才生成记录。

同一码重复扫描只定位原行，不按扫描次数累加数量。同一准备明细只能有一个有效或成功的入库申请。驳回、移除或取消申请后可重新核对，已成功入库的明细不可再次入库。

网络响应丢失时使用“重试原请求”，系统保持原客户端事件标识和原参数。不要用新明细代替尚未确认结果的请求。

## 项目管理与合同关系

入口为“库存 → 库存工具 → 项目管理”。项目号使用统一档案，每个编号只建一份；新建时去除首尾空白并校验唯一，重复编号提示选择已有项目。项目号是最多 100 字符的文本，支持中文、字母、数字及符号，`00123` 的前导零会保留。

入库填单、普通入库扫码和归属维护均选择已有项目，不能把未登记的搜索文字直接作为新项目保存。同一项目可被多张单据和多条库存引用；每张入库单选择一个合同，因此同一个项目可以分别建立使用合同 A、合同 B 的两张入库单。项目与合同没有强制一对一关系，验收日期和质保期限仍由各自合同决定。

升级会将现有库存和入库单中的项目归入统一档案，并建立项目关联。原项目文本、二维码标识及版本、库存数量和历史记录保持原值。已被单据或库存引用的项目号不能直接改名或删除；归属调整使用原“合同与验收”流程。停用项目不能用于新入库，原有库存仍可出库。

## 合同与质保维护

在库存列表选中设备，打开“合同与验收”，点击“更新合同验收日期及质保”。验收日期即合同起始时间，允许入库后补填或更新。保存前核对关联明细数量、填写原因；保存后同一合同的所有关联设备统一更新验收日期、质保月数和到期日。无需选中库存行时，可从库存页“库存工具 → 合同管理”选择已有合同或新建合同；填单时仍可就地新建合同。

验收日期为空时显示待验收。到期日期按验收日期加自然月计算；例如 2024-02-29 加 12 个月为 2025-02-28。采用中国业务日期，到期日当天仍在保，次日过保。

未使用的待入库记录可修改公共项目、合同及库位。未入库明细可修改准备数量；当前归属可按权限修改。修改项目或合同会递增标签版本，必须更换实物标签；修改验收或质保无需换码。

库存列表选中一行后，使用“合同与验收”维护已入库明细。系统同步该来源明细的当前库存项目；原审批与出入库记录保持办理时快照。草稿、待审批、冻结或其他业务占用会阻止归属修改，须先处理相关申请。

取消待入库记录仅适用于没有有效申请、已成功入库或历史补录的记录。修改、取消、打印和补打均保留操作审计。

## 出库与审批

1. 在原扫码出库页面选实际库位，扫描完整标签。
2. 系统自动填入设备ID、设备名称、项目和合同号核对栏，显示当前库存与可用数量。只有一个实际库存库位时自动带出库位；多个实际库位时须选择本次出库位置。扫码枪回车先填充，核对后点击“加入待出库”。
3. 填写出库数量、用途和备注，核对后加入草稿。加入成功即冻结本次申请数量，提交时不重复冻结。
4. 原审批人审批通过时原子扣减库存并释放冻结；驳回、取消或过期释放冻结，不扣库存。继续沿用禁止自审等规则。

同一明细移库或拆分后仍保留来源关联。出库只使用选定实际库位的库存；不能跨库位补足数量。两个相同设备、项目、合同的入库明细也不会合并来源。

## 历史库存补录与盘点

历史库存的来源关联允许为空，原项目仍保存在 `batch`。升级不会猜测合同，也不会创建虚假入库。

在库存列表选中历史行，进入“合同与验收”，核对当前整行数量及本次归属数量，选择合同并填写原因。若一行包含多个合同，只填写本次确认的数量；系统拆分该部分，剩余部分分别核对补录。补录前后库存总量不变，不生成扫码入库事件。补录完成后打印完整标签，后续使用完整码办理。

扫码页面只有统一入口，不再区分“完整标签业务”和“历史旧码兼容”；已有设备码可在同一个入口识别并自动显示设备ID和名称。设备基本码未携带项目或合同信息时，不能猜测合同号；合同核对栏显示“此码未包含合同号”。普通设备出库仅有一个匹配项目时自动选中，存在多个项目则由操作员明确选择。普通操作员不能通过旧码为没有匹配历史库存的设备创建新入库。已关联完整明细的库存不能被基本码或旧库存码冒用。管理员仍保留原生库存管理能力。

库存导出、记录导出和盘点模板增加合同、明细标识、验收日期、质保月数及到期日。库存表展示当前值，出入库记录展示历史快照。汇总数量可以合计，合同或质保字段不一致时显示“多种”。

盘点时同设备、项目、库位存在多个明细必须携带导出的明细标识；缺失标识导致歧义时整批拒绝。预览确认后提交按预览中的精确库存行处理，避免修改其他来源。盘点表中的合同和质保列作为参考，维护这些信息应使用专门业务入口。

## 设备资料与库存盘点导入

库存列表的“导入”菜单提供两个入口，都支持 `.xlsx` 和 UTF-8 CSV；先下载对应的专用模板，再上传预览、勾选核对确认、点击“确认整批提交”。任何一行存在错误都会阻止整批保存；上传预览本身不新增设备或改变库存。已有设备、库存或占用在预览后发生变化时，须重新预览。

- “设备资料导入”：包含设备ID、名称、品牌、分类完整路径、型号、单位、规格、备注。设备ID匹配已有设备；新增设备可留空，由系统生成内部ID。新增设备必须提供名称、分类和单位。已有设备的空白可选资料保留原值；同一文件内重复设备ID会被拒绝。资料导入不增加实物库存；有业务数据的设备不能通过导入更改ID或单位。
- “库存盘点导入”：填写当前实盘总数，不能把增加数量当作总数填写。例如现有 10 件、表中填 8 件，会调整到 8 件。项目号最多 100 字符；同一编号关联同一项目档案，新编号在实际提交创建库存时登记。盘点数量不能低于冻结和业务占用；精确匹配设备、项目、实际地点和来源明细，不能跨地点或来源调整库存。合同和质保列仅供参考，不通过盘点导入修改。

设备ID和项目号在 Excel 中应按文本填写，以保留 `00123` 等前导零。涉及完整标签的库存，优先从库存明细导出后修改盘点数量，保留“明细标识”列。导入成功后，共享项目选择列表会刷新；同一已完成任务重试不会重复落账。

## 完整码协议与接口

新打印的完整码使用紧凑格式，仅保存 `WMS1:` 前缀、32 位大写十六进制明细 UUID 和标签版本。例如：

```text
WMS1:47F10C0F07774F8595DDCE0A81592994:1
```

版本为 1 时共 39 个 ASCII 字符，项目和合同的长度不再增加二维码密度。扫码时仍由服务器自动读取设备、项目、合同、验收、质保和数量，操作员核对流程相同，需要连接仓库系统。明细 UUID 不可变，归属调整仍递增版本并要求换标；原来打印的 JSON 完整码继续校验和识别，不需要仅因格式升级重打。

50 × 30 mm 标签使用 26 mm 二维码、H 级纠错及四模块留白。标签预览及打印页保留设备名称、设备编号、项目和合同，去掉可见“标签版本 1”，底部增加“广州南沙智慧城市大数据有限公司”；版本仍用于内部校验。较短的码和较高纠错用于提高擦蹭后的识别容错，严重损坏定位角或大面积破损仍可能需要重打，现场应使用实际打印机和扫码枪验收。

预览与打印采用相同的 50:30 比例及字段排版，名称与二维码黑色码面顶端对齐；长字段按相同长度规则缩小字号并自动换行。公司名固定居中放在底部，以分隔线与设备信息区分开，不占用二维码留白。

服务端校验格式、UUID、正整数版本、当前记录状态及实际库位。JSON 旧码还会核对编码中的设备、项目和合同；字段不一致、旧版本或已取消标签均不能直接办理出入库。落账依据来自服务端明细。

| 接口 | 用途 |
|---|---|
| `GET/POST /api/stock/wms/projects/` | 查询启用项目、新建唯一项目；入库业务可传 project_id，或传已登记的 project 编号，二者同时传入须一致 |
| `GET/POST /api/stock/wms/contracts/` | 查询、新建；POST 带 pk 编辑，preview=true 查看影响；实际更新带 reason 和 expected_updated_at |
| `GET/POST /api/stock/wms/receipts/` | 恢复自己的待入库记录；使用 request_key 幂等保存 |
| `POST /api/stock/wms/receipts/{pk}/` | 修改未使用记录的公共信息，带原因 |
| `POST /api/stock/wms/receipts/{pk}/cancel/` | 取消未使用记录，带原因 |
| `GET/POST /api/stock/wms/details/{pk}/` | 查询和修改当前明细，更新带 label_version 与 reason |
| `POST /api/stock/wms/labels/resolve/` | 验证 barcode；可带 receipt 与 location，返回权威明细及库存余额 |
| `POST /api/stock/wms/legacy/{stock_pk}/` | 显式核对历史库存总量、归属数量和合同，使用 request_key 幂等补录 |
| `GET /api/stock/wms/changes/` | 按 contract、receipt 或 detail 查询操作人、时间、原因及前后值 |
| `POST /api/stock/scan/inbound/` | 复用原审批链，完整码入库带 receipt_id；实际数量不同带 quantity_confirmed=true |
| `POST /api/stock/scan/outbound/` | 完整码出库，带实际 source_location、数量与用途 |
| `POST /api/label/local/jobs/` | 原本地打印接口支持 model_type=wmsreceiptdetail；独立数量传 copies=1 和 item_copies（明细 ID → 数量），返回 total；重试和补打保留原数量映射 |

业务维护继续要求库存变更权限，基础资料权限不增加；创建审批草稿要求原库存角色和库位权限。OAuth 写操作要求 `stock` 的 change scope；完整码解析为只读请求，接受现有 read/view scope。

## 发布及回退操作

本次新增迁移为 `stock.0134_contract_warranty`、`stock.0135_complete_label_length`、`report.0034_contract_warranty`，以及项目档案补充迁移 `common.0050_warehouse_project_archive`、`stock.0136_warehouse_project_archive`、打印数量迁移 `report.0035_localprintjob_item_copies`。所有旧迁移保持不变。迁移遇到原项目档案中首尾空白归一后重复或空白的编号时会中止，须核对后再迁移，不自动合并已有独立档案。

实际发布前执行以下步骤，并将命令、时间、备份位置及负责人写入发布记录：

1. 备份目标数据库、media 中的标签模板、当前镜像与前端构建版本。导出迁移前库存数量、项目及审批状态作为对比基线。
2. 在目标库的隔离副本演练迁移，比较上述基线。已有自动化新库迁移演练不能替代目标库备份副本演练。
3. 在维护窗口停止业务写入，先部署后端代码并运行 `python manage.py migrate --noinput`，再重启后端及打印 worker。挂载新代码而未迁移时，应用的启动检查会提示缺少迁移并拒绝启动。
4. 确认存在唯一、启用的 `WMS Complete Receipt Label` 模板，模型为 `wmsreceiptdetail`，默认尺寸为 50 × 30 mm。已注册模板文件存于 media，须在备份后同步最新 `wms_complete_receipt.html`，仅替换源代码中的模板不会更新已注册文件。原本地打印配置、QZ 证书和队列沿用现有部署配置。
5. 部署新前端构建，确认扫码审批开关启用。使用操作员和独立审批人完成填单、打印、扫码入库、部分出库、驳回及修改换标。
6. 使用真实打印机和扫码枪验收中文、最长常用编号、打印缩放、二维码密度与连续扫码焦点。超长编号会缩小字号，须确认现场可读性后上线。
7. 完成库存、项目、审批对比后开放写入，保存发布版本和验收记录。

回退优先停止新业务、关闭新入口并保留新增表和业务数据。保留新字段兼容的后端；如仅界面异常，可先回退前端入口。不要直接倒退删除新增表，也不要让旧业务写入绕过已关联明细的规则。恢复备份须确认备份后是否有业务写入，并单独制定数据恢复方案。
