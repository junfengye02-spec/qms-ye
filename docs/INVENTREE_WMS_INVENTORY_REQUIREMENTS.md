# InvenTree WMS 基础库存管理需求说明书

> 文档状态：本次沟通确认范围版  
> 更新日期：2026-09-07  
> 实施补充：按用户后续确认，暂不增加“台、套、米”等中文业务单位，使用原生单位校验。  
> 使用范围：设备资料、当前库存、两级地点、项目、扫码入出库、现有审批、期间入出库记录查询、日常盘点导入和基础导出。

## 1. 已确认的范围

本系统以基础库存管理为主，继续在当前项目上开发，不按完整ERP扩展。

用户已确认：

1. 库存页面查看现在剩多少，不查询过去某天的库存余额。
2. 支持选择时间段，查询这段时间的入库、出库记录及数量。
3. 支持日常上传Excel盘点表，调整当前库存。
4. 一级地点和二级地点都可以直接存货。
5. 项目必填，每笔库存都属于一个项目。
6. 现有数据全部是测试数据，可以清理，不需要旧数据迁移和历史账还原。
7. 扫码入库、扫码出库和审批沿用现有基础流程。

本期不包含：调拨、跨项目库存转移、采购／销售／生产流程改造、期初期末报表、历史时点库存、历史补记账、旧项目补录、新审批流程、独立报表中心、项目管理模块。

以下实施约定用于把已确认的范围写清楚，不增加新的业务模块。本文只调整需求，不代表已经修改代码或清理测试数据。

## 2. 设备资料

设备表示一种设备，复用现有Part，不代表每台实物设备的单独序列号。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 设备ID | 是 | 复用Part.IPN，作为业务编码和设备码匹配依据 |
| 设备名称 | 是 | 设备显示名称 |
| 设备分类 | 是 | 复用现有分类树，不新增“类型”字段 |
| 单位 | 是 | 沿用原生单位字段和校验，例如 count、m；暂不扩展中文业务单位 |
| 品牌 | 否 | 新增资料字段 |
| 型号 | 否 | 新增资料字段 |
| 规格 | 否 | 新增资料字段 |
| 备注 | 否 | 设备长期备注 |

规则：

- 设备ID不是数据库自增主键；去首尾空格后，按忽略大小写判断唯一，沿用现有校验。
- 查询和导出统一显示设备ID；现有设备码、库存项码和已绑定条码继续沿用，不扩展新的条码体系。
- 分类可按当前分类及下级查询；导入匹配已存在、允许挂设备的分类，不自动建分类。
- 有库存、业务记录或活动申请的设备，在本次页面使用停用方式管理，不提供物理删除。
- 有上述业务数据后，不通过普通编辑或导入修改设备ID和计量单位，避免换码、换单位造成记录混淆。
- 设备改名或停用，不改变已有入出库记录中的设备信息快照。

## 3. 项目

- WMS中的“批次号”改为显示“项目”，数据库继续复用StockItem.batch，不改列名，不另建项目管理模块。
- 入库和库存盘点导入都必须填写项目，不提供公共库存或“未归属项目”入出库模式。
- 入库可输入项目，也可选择已有项目；出库只能从所选设备、实际地点的现存库存中选择项目。
- 项目去除首尾空格；沿用文本精确匹配，不自动改大小写或合并不同项目。输入时展示已有项目供选择，减少错字。
- 一个项目可有多种设备，同一设备可属于多个项目，同一项目的设备可放在不同地点。
- 只扣指定项目的库存，不自动借用其他项目。
- 不提供跨项目转移功能；盘点表中的项目用于定位库存，不能被解释成把另一个项目的库存改名或转入。
- 已落账记录保存当时的项目，后续操作不能改写历史记录。
- 旧数据为测试数据，不开发旧空项目补录或批次转换功能。

## 4. 一级地点和二级地点

- 复用现有地点树，一级、二级都可以作为实际存货地点。
- 入库、出库、盘点必须指定实际存货地点；页面显示完整路径，避免同名二级地点混淆。
- 查看一级地点时，提供“含下级汇总”和“仅本地点”范围，默认含下级；二级地点查看自身库存。
- 做扫码或盘点时，选哪个地点就只操作哪个地点的直属库存，不自动操作下级或其他地点。
- 页面和导出必须明确区分一级地点汇总量与直属库存量。
- 库存明细每行只属于一个实际地点；用于盘点的明细导出不插入一级地点汇总行。

例：一级地点A直属库存5个，二级地点A/B库存3个。查看A含下级时显示8个，查看A仅本地点时显示5个。从A出库只能扣A直属库存；盘点A填4、A/B填2，调整后分别为4和2，A含下级合计为6。

## 5. 当前库存查看

提供库存汇总和库存明细两个视图。

| 视图 | 每行表示什么 | 主要字段 |
| --- | --- | --- |
| 库存汇总 | 同一设备在当前查询范围内的合计 | 设备ID、名称、品牌、分类、型号、单位、规格、库存数量、冻结数量、可用数量、项目数量、设备备注 |
| 库存明细 | 设备＋项目＋实际存货地点 | 上述设备资料、项目、地点完整路径、库存数量、冻结数量、可用数量、最后库存变动时间、库存备注 |

数量规则：

- 库存数量：现有系统认定的在库余额，复用当前库存计算方式。
- 冻结数量：出库扫码成功加入草稿后产生的占用，包括活动草稿和待审批单中的冻结。
- 可用数量：沿用现有计算，扣除扫码冻结及已有业务占用，不取消现有库存保护。
- 汇总从现有库存明细计算，不新增“总库存”字段或第二套余额。
- 项目、地点等筛选后的数量和项目数量都只统计当前查询范围，不能一部分用全量、一部分用筛选结果。
- 项目数量按当前范围内有正库存或活动冻结的不同项目去重统计。
- 库存明细默认显示有库存或有冻结的记录，可选择包含零库存；隐藏零库存不删除业务记录。
- 最后库存变动时间指数量或实际库存归属发生变化的时间，不使用设备资料编辑时间代替。
- 库存备注只表示库存项备注，不被扫码备注或盘点备注自动覆盖；多条库存合并展示时不任意挑选一条备注代替全部。

筛选：设备ID／名称、品牌、分类、型号、项目、地点范围、有无库存、有无冻结、关键字。

当前库存页面不提供“过去某天余额”或“期初／期末”功能，也不把最后更新时间筛选当作历史库存。

同一展示组合可能对应多个原生库存项。正常入库复用明确兼容的匹配项；多条无法唯一选择时沿用现有库存项选择机制，不自动合并。盘点不能唯一定位时提示处理后重新导入，不新增自动分摊算法。

## 6. 扫码入库

操作字段：设备ID（扫码或手输）、数量（默认1）、项目（必填）、实际目标地点（必填，可扫描地点码）、备注（选填）。

流程：

1. 查找设备，核对项目、地点和数量。
2. 找到唯一兼容库存项则使用；有多个候选则明确选择；没有对应库存项时准备新建。
3. 审批开启时仅保存草稿／申请，审批前不增加库存，也不提前创建新库存项。
4. 审批成功后整单落账；审批关闭时沿用直接入库。
5. 未知设备保留快速建档，补齐设备名称、分类、单位和本次项目；审批模式下先保存资料，审批成功时才创建设备及库存。
6. 驳回、撤销、超时或落账失败，不增加库存。

数量必须大于零，沿用现有最多5位小数的数量精度，不新增单位换算或序列号作业流程。

## 7. 扫码出库和审批

出库字段：设备ID（扫码或手输）、数量（默认1）、项目（从现存库存选择，必填）、实际来源地点（必填）、用途（必填）、备注（选填）。

出库规则：

- 只从指定设备、项目、实际地点的可用库存扣减，不跨项目或地点补扣。
- 数量大于零，不能超过可用量；未知设备不允许出库。
- 审批开启时，扫码成功加入草稿即冻结，当前库存暂不减少；审批成功才扣减实物库存。
- 驳回、撤销、超时和移除草稿明细沿用现有冻结释放机制。
- 审批关闭时沿用直接出库。

审批规则：

- 一张申请固定方向和实际地点，可以有多行和多个项目；每行保存自身的项目、数量、用途和备注。
- 用途可沿用上次填写作为录入默认值，操作者能修改；同单允许不同用途。
- 沿用现有按地点配置的审批人和申请人不能自审的规则。
- 整单审批、整单落账；任一行失败，整单不部分执行。
- 审批执行失败沿用现有可重试状态及错误提示，冻结继续保留，直到成功或驳回、撤销、超时。
- 不新增多级审批、项目审批路由或独立盘点审批。
- 已完成申请不提供直接撤销改账；本期不新增冲销模块。

同一次扫码的网络重试只处理一次；相同设备连续独立扫描三次是三个操作，不应按设备码去重。方向、数量、项目、地点、用途、备注等内容变化不能冒用同一次请求编号。

## 8. 按时间段查询入出库记录

用户选择开始日期和结束日期，查询期间的入库或出库记录及数量，同时可到库存页面查看现在的余额。

本期不展示期初库存、期末库存、历史库存或将盘点调整与扫码记录混合计算的“库存净变化”。

记录字段：

| 入库记录 | 出库记录 |
| --- | --- |
| 设备ID、设备名称、单位、入库数量 | 设备ID、设备名称、单位、出库数量 |
| 项目、目标地点 | 项目、来源地点、用途 |
| 入库人、正式入库时间 | 出库人、正式出库时间 |
| 备注、审批状态、审批人 | 备注、审批状态、审批人 |

时间和人员：

- 入库人／出库人是发起人，审批人单独记录。
- 正式入出库时间是库存成功落账的时间；例如9月1日扫码、9月2日审批成功，数量统计计入9月2日。
- 按中国时区统计，日期区间包含开始日和结束日整天。9月1日至7日包括7日晚间，排除8日零点及之后。
- 支持今天、昨天、本周（周一开始）、本月、上月和自定义日期范围。
- 现有“我的申请／待我审批／操作记录”继续展示申请状态和扫码时间；没有正式落账时间的待审批或失败记录不出现在按正式时间筛选的成功业务数量中。

筛选与统计：

- 支持时间、设备ID／名称、品牌、分类、型号、项目、地点、发起人；出库另外支持用途筛选。
- 入库和出库分别查看，列表展示成功记录数、设备种类数和数量小计，不另建复杂统计页面。
- 成功记录数按落账的扫码明细行计算，不按审批单数计算；设备种类按设备去重。
- 只合计成功落账的实际数量；草稿、待审批、失败、驳回、撤销、超时不计入。
- 按当前筛选统计所有符合条件的记录，不只统计当前页。
- 不同单位分别合计，例如“10台、30米”，不合成“40件”；同设备显示其自身小计。
- 设备、人员、项目、地点历史展示使用记录快照；品牌、分类、型号筛选按当前设备资料，不增加这些资料的历史版本管理。

## 9. 设备资料导入

模板：

```text
设备ID、设备名称、品牌、设备分类完整路径、型号、单位、规格、备注
```

- 先预览，再确认。设备不存在则新增，存在则展示资料更新内容。
- 新设备必须补齐第2章必填资料；更新时未提供的列和空白可选单元格均保留旧值，清空资料走单条编辑。
- 文件内重复设备ID报错，按去空格、忽略大小写判断重复。
- 分类必须唯一匹配系统已有可用分类，不自动新建。
- 有库存、记录或活动申请的设备，单位不能通过导入修改；设备ID用作匹配键，不作改码工具。
- 有错误行阻止整批提交；提交时再校验，整批成功或整批回滚。预览后目标资料被其他人修改时，要求重新预览。

## 10. 日常库存盘点导入

盘点表中的数量是实际盘点总数，不是本次增加量。系统原有10个、表内填8个，落账后为8个，调整量为-2。

模板：

```text
设备ID、设备名称、品牌、设备分类完整路径、型号、单位、规格、项目、地点完整路径、盘点数量、盘点日期、盘点备注
```

字段和匹配：

- 设备ID、项目、地点完整路径、盘点数量必填；项目不能为空。
- 已有设备按设备ID匹配，资料列不顺带修改主档；填写的名称、分类或单位与现有资料不一致时提示并阻止提交。
- 未知设备允许按表内资料创建，必须补齐名称、分类、单位等必填资料；同一新设备在多个项目行出现，只建档一次，资料冲突报错。
- 分类和地点必须已存在、能唯一匹配，不自动创建；地点可以是一级或二级，必须允许实际存货。
- 一行只表示指定设备、项目和地点的直属库存；不能把一级地点含下级的汇总量写成一级直属盘点量。
- 同一设备、项目、实际地点的重复行报错；多条原生库存项无法安全定位时阻止提交并提示，不任意覆盖。
- 盘点数量允许零、不允许负数，精度沿用现有库存数量规则；表中未出现的库存保持不变，不能自动清零。
- 盘点日期选填，只记录实际盘点日期；默认提交当日。它不改变正式落账时间，不允许用旧日期回写历史库存。

预览与落账：

1. 预览展示系统当前数量、盘点数量、调整差额、冻结数量，以及新增设备、新增库存、增加、减少、无变化和错误行。
2. 确认后调用现有库存调整能力，将对应库存调整到盘点数量，保存操作人、正式落账时间、盘点日期、前后数量和备注。
3. 预览后目标库存数量、项目、地点或占用发生变化，阻止提交并要求重新预览；不能用旧预览覆盖新出入库结果。
4. 调整后的数量不能低于冻结及其他已有占用量。例如冻结8个、盘点5个时，阻止导入并提示关联申请；通过现有撤销等流程处理占用后再盘点，不自动释放冻结。
5. 任意错误行阻止整批提交，正式提交整批成功或整批回滚，不留下部分新设备或部分调整。
6. 同一导入任务重试只执行一次；重新上传同一文件属于新任务，必须重新预览确认。数量没变化时不重复增减。
7. 盘点在有权限的人确认后直接落账，不新增盘点审批流程。
8. 盘点调整保留在导入结果及库存流水中，不计入扫码入库／出库记录数量，也不开发独立盘点分析报表。

盘点表必须反映当前实盘结果。上传前已发生出入库的旧盘点表，不能未经重新核实就覆盖当前库存；系统的预览后变更校验不能替代现场盘点核实。

## 11. 基础导出

| 导出对象 | 内容 |
| --- | --- |
| 设备资料 | 第9章设备资料字段 |
| 当前库存汇总 | 第5章库存汇总字段，数量是当前筛选范围合计 |
| 当前库存明细 | 第5章库存明细字段，地点使用完整路径，保留实际存货地点粒度 |
| 入库记录 | 第8章入库记录字段 |
| 出库记录 | 第8章出库记录字段 |

- 导出全部匹配记录，不只导出当前页；与页面的筛选范围、数量口径、数据权限一致。
- 导出中文业务字段，时间按中国时区显示；入出库导出包含单位。
- 库存汇总导出不能直接当作盘点表上传；盘点使用专用模板或按实际地点导出的明细整理填写。
- 不提供入出库记录导入、期间库存导出或历史库存导出。

## 12. 权限与记录保留

- 沿用现有设备、库存、申请、审批和审计权限，不新建权限管理模块，也不额外拆分两个入库／出库权限。
- 设备导入要求对应设备新增／修改权限；盘点导入要求对应库存新增／修改权限，创建未知设备时还要求设备新增权限。
- 列表、统计和导出遵守相同数据可见范围，不因统计或导出扩大权限。
- 扫码事件继续记录设备ID／名称、项目、实际地点、单位、申请人、审批人、数量、前后余额、扫码时间、正式时间、用途、备注、状态及失败原因。
- 盘点记录保存导入任务、操作人、目标设备／项目／地点、前后数量、差额、盘点日期和正式时间；不为盘点虚构扫码时间或审批人。
- 设备备注、库存备注、扫码备注、盘点备注分别保存，互不自动覆盖。
- 正式业务开始后保留操作记录；隐藏零库存或停用设备不删除这些记录。测试数据可清理的约定不等于允许随意删除正式记录。

## 14. 验收与实施顺序

验收至少覆盖：

1. 同设备跨项目、跨地点汇总正确；项目筛选后不混入其他项目数量。
2. 一级地点直属库存与下级库存分别展示和操作，一级含下级汇总不重复统计。
3. 项目为空时，扫码入库和盘点导入均不能提交。
4. 从指定项目或实际地点出库不足时，不自动借用其他库存。
5. 入库审批前数量不增加；出库加入草稿即冻结，审批前实物数量不减少。
6. 整单审批失败不部分落账；驳回、撤销、超时后冻结正确释放。
7. 两人同时出库最后一件，最多一个成功；网络重试不重复入出库，独立扫码正常累计。
8. 按正式入出库日期查询正确，跨天及结束日不漏记，不同单位不混加。
9. 盘点10改8后余额为8，调整为-2，不计入扫码出库数量；没有出现在表中的库存不变。
10. 冻结8但盘点5、未知地点、重复行、非法数量、目标库存多条歧义、预览后库存变化，均阻止盘点提交并给出可理解的提示。
11. 一行盘点失败整批不落账；同任务重试不重复调整或创建设备。
12. 页面与导出范围及统计一致，零库存隐藏或设备停用后记录仍可查询。

实施顺序：设备资料和必填规则 → 项目及两级地点库存查看 → 扫码与现有审批适配 → 入出库日期查询和数量统计 → 设备及盘点导入 → 基础导出 → 测试环境验收。

不把期初期末报表、旧数据兼容工程或未使用的原生业务改造加入本期任务。
