# 合同与质保管理及完整二维码执行计划

日期：2026 年 10 月 8 日  
状态：P0–P5 代码实现及自动化验证已完成，P6 自动化及完整预览系统真实浏览器验收通过；真实打印机/扫码枪、正式目标库副本迁移演练及实际发布待完成。  
代码目录：`InvenTree/`。

## 1 目标与确定范围

在现有设备资料、扫码出入库、审批和本地打印功能上扩展合同管理及质保信息。管理员维护基础资料，操作员负责其余业务录入、打印、扫码及提交审批，审批人沿用现有职责。

- 复用现有设备基本信息页面，不新建设备档案体系。
- 项目号、合同号关联到设备入库明细，不固定到设备基础资料。
- 项目号使用唯一项目档案，业务单据和库存引用已有项目；同一项目可以使用多个合同。
- 某种设备的一条入库明细可以包含多台实物，同一明细共用一个完整二维码，不实施单台序列号管理。
- 验收日期即合同起始时间；可在入库后由后台补填或更新，质保按合同统一计算，不提供明细覆盖。
- 扫码入口统一，默认直接扫码；库存页提供“入库填单与打印”和“合同管理”，日常出入库申请页只保留扫码、汇总和审批相关功能。
- 基本二维码仅包含设备编号，保留为辅助能力，不打印、不作为业务必经步骤。
- 完整二维码包含设备编号、项目号、合同号，并增加系统生成的明细标识和版本，以区分同一合同下重复入库的相同设备。
- 操作员在库存页“入库填单与打印”选择设备、填写业务信息、保存并打印，贴标后到“出入库申请”扫码核对并提交原有审批。
- 出库扫描完整码自动带出项目和合同，保留数量、库位、用途等现有要求。
- 出库成功加入草稿即冻结申请数量；审批通过扣减库存；驳回、取消、过期释放冻结。
- 完整码生成后允许修改归属；新码替换旧码，历史业务快照不改写。

不增加用户填写的批次号，不把打印成功当作入库成功，不将扫码一次直接等同于收到整批实物。

## 5 操作员入库与打印任务

库存列表提供“入库填单与打印”，管理新到货准备单与标签；出入库申请页直接扫码。已保存的入库单可转到该单的实物扫码核对，继续共用同一份待入库数据。

### 5.1 填写及打印

- [x] 支持按设备编号、名称搜索并选择已建基础资料，不要求扫描屏幕基本码。
- [x] 公共区域填写项目、合同、库位；选择合同自动带出验收和质保默认值。
- [x] 添加设备明细并填写数量，验收日期和质保月数统一使用合同设置。
- [x] 保存后直接提供完整标签预览和打印，无需再次“应用”归属信息。
- [x] 扩展现有本地打印模型以接受待入库明细，不能要求先正式入库才能打印。
- [x] 标签包含完整二维码及可读的设备编号、名称、项目号、合同号。
- [x] 支持批量打印、每条设备独立数量、单条补打；打印数量与入库数量不是同一业务字段，任务总张数按各行合计，失败重试保留原数量。
- [x] 预览和实际标签去掉可见“标签版本 1”，加入“广州南沙智慧城市大数据有限公司”，内部版本校验保留。
- [x] 采用较短二维码、H 级纠错、四模块留白；对实际 PDF 做 203/300 dpi 解码和擦除、划痕模拟，记录严重污损识别限制。
- [x] 标签大小和二维码密度在现有打印模板上验证，长项目号或合同号不能裁切关键信息。
- [x] 打印失败可重试，不能重复创建业务明细或改变库存。

### 5.2 扫码核对

- [x] 扫实物完整码定位当前明细，自动带出信息，确认实际数量后加入入库草稿。

- [x] 默认一次扫码定位一条明细，不按重复扫描次数自动累加数量。
- [x] 同一码已加入时定位原行并提示，不重复新增。
- [x] 其他待入库记录的码、旧码、取消记录的码给出明确错误。
- [x] 显示待核对与已核对明细；未核对行不自动提交。
- [x] 确认部分明细提交时明确显示未提交行，保留后续处理入口。
- [x] 提交后沿用现有审批；审批通过才增加库存。
- [x] 驳回后可修改再申请，但保留原审批历史且避免重复落账；原单取消后不能继续办理业务。
- [x] 每次操作后恢复扫码输入焦点，支持扫码枪回车结束输入，处理期间防止串码。

## 9 执行顺序与阶段完成条件

| 阶段 | 执行内容 | 完成条件 |
|---|---|---|
| P0 基线核对 | 检查仓库规范、未提交变更、现有接口及权限；确认扫描、打印运行方式 | 形成具体变更清单，确认不覆盖已有工作 |
| P1 数据与规则 | 新模型、迁移、合同统一日期、到期计算、来源关联、历史快照 | 模型及关键业务规则测试通过，旧数据保持原值 |
| P2 服务及识别 | 合同与准备接口、完整码协议、明细库存定位、幂等与状态约束 | API 可完成准备到审批落账链路，重复与并发不重复记账 |
| P3 入库与打印 | 操作员填单、设备选择、模板扩展、标签打印和核对 | 可在未入库时打印，实物扫码能定位对应明细 |
| P4 出库及展示 | 扫完整码出库、冻结、审批展示、字段和筛选 | 无需手填项目合同即可完成出库，库存及冻结数量准确 |
| P5 变更及兼容 | 归属修改、旧码失效、历史补录、盘点和导入导出 | 历史数据可迁移使用，明细差异不会被合并丢失 |
| P6 集成验收 | 权限、异常、实物打印扫码和回归测试 | 下节验收矩阵通过，形成测试结果及上线步骤 |

依赖顺序为 P0 → P1 → P2 → P3 → P4 → P5 → P6。前后端接口在 P2 固定后再完成页面集成。

| 准备 10 台实际到货 8 台 | 明确确认申请数量，审批只入库 8 台，余量不自动入库 |
| 入库待审批、通过、驳回后重提 | 通过前无库存，通过只落账一次，历史保留 |
| 库存 10 台出库 3 台 | 草稿冻结 3，可用按现有占用规则减少；通过后库存 7、对应冻结释放 |
| 出库取消、驳回、过期 | 冻结释放，库存未扣减 |
| 并发超额出库及重复审批 | 不超卖、不重复扣减 |
| 项目或合同变更后扫旧码 | 拒绝旧归属交易并提示换标 |
| 有待审批申请时修改归属 | 拒绝直接修改并提示处理关联申请 |
| 验收或质保修改 | 到期时间更新，原标签仍有效 |
| 旧数据升级及补录 | 数量和历史项目不变，补录不生成虚假入库 |
| 多明细盘点及汇总 | 无歧义误写，数量汇总正确，差异字段不错误归并 |
| 越权直接调用接口 | 后端拒绝，不仅依赖前端隐藏按钮 |
| 真实打印机及扫码枪 | 标签可读，中文和长编号正确，连续扫码焦点稳定 |
