# 项目原生功能与二开功能说明

整理日期：2026-09-20。

本项目基于 **InvenTree 1.5.1** 二次开发。原生系统提供物料、库存、采购、销售和生产管理能力；当前二开重点是设备／成品仓库的扫码作业、项目库存、整单审批、库存冻结和操作追溯。

本文根据当前源码、二开功能清单以及 2026-09-07、2026-09-09 的验收记录整理，说明代码和文档中已有的功能。具体部署环境是否更新、是否开启审批或通知，需要以该环境的实际配置为准。

## 一、原生 InvenTree 的功能

| 模块 | 原生能力 | 业务用途 |
| --- | --- | --- |
| 物料档案 | 物料编码、名称、分类、单位、图片、附件、参数等 | 建立统一商品、零件或设备资料 |
| 库存管理 | 库存数量、库位、批次、序列号、状态等 | 查询东西在哪里、还有多少 |
| 仓库与库位 | 多层级地点树 | 按仓库、区域、货架等层级组织存放地点 |
| 库存操作 | 增加、扣减、盘点、移动、拆分、合并 | 处理日常库存变化 |
| 采购管理 | 供应商、采购订单、采购明细、收货入库 | 管理向供应商采购及收货的过程 |
| 销售管理 | 客户、销售订单、库存分配、发货及退货单 | 管理订单到交付的过程 |
| BOM 物料清单 | 产品组成、所需零件及数量 | 定义一套产品需要哪些物料 |
| 生产管理 | 生产工单、物料分配与消耗、产出库存 | 将零部件组装为成品 |
| 库存追溯与测试 | 库存变动记录、序列号追踪、测试结果 | 追查库存流转及检测情况 |
| 标签与报表 | 模板化标签、条码、报表打印 | 打印物料、库存项等标签与报表 |
| 用户与权限 | 用户、用户组、角色及业务权限 | 控制不同人员可以查看和执行的操作 |
| 数据与扩展 | 导入导出、REST API、插件 | 批量处理资料及扩展系统 |

原生典型业务流程：

**采购订单 → 收货入库 → 库存管理 → 生产组装（可选）→ 销售订单 → 分配库存 → 发货。**

这些原生模块仍保留在项目代码中。当前仓库业务可以只使用其中一部分，不必启用完整的采购、生产和销售流程。

## 二、原生概念与当前业务的对应关系

| 当前业务叫法 | 底层对应 | 说明 |
| --- | --- | --- |
| 设备／商品资料 | `Part` | 表示一种设备或商品的资料，不必然代表某一台实物 |
| 设备ID／商品编码 | `Part.IPN` | 用于识别设备类型或商品；二开增加唯一性和冲突保护 |
| 库存项 | `StockItem` | 记录具体地点、项目等上下文中的库存数量 |
| 仓库／实际地点 | `StockLocation` | 沿用原生地点树 |
| 项目 | `StockItem.batch` | 将原生批次字段用于当前项目库存归属，现有字段长度为100字符 |
| 出入库流水 | 原生库存流水＋扫码业务事件 | 原生流水记录库存变化，扫码事件补充申请和操作上下文 |

当前的“项目”用于区分库存归属，不是独立的项目管理模块，不包含预算、进度、合同等项目管理功能。当前扫码中的“设备ID”也不应直接理解为每台实物的唯一序列号。

## 三、当前二开功能

### 1. 设备资料管理

- 在原生物料资料上新增品牌、型号和规格。
- 建档要求填写设备ID、名称、分类和单位。
- 支持新建、编辑、停用和批量导入。
- 已经产生业务数据后，保护设备ID和单位，避免历史记录含义发生变化。
- 单位继续使用原生单位字段和校验，未另建中文业务单位体系。

### 2. 按设备、项目、地点管理库存

- 库存按“设备＋项目＋实际地点”匹配。
- 同一设备可以属于不同项目，也可以存放在不同地点。
- 扫码出库不能混扣其他项目的库存，也不会自动扣减子地点库存。
- 查询支持“仅本地点”和“含下级地点”，明确区分直属库存和汇总库存。

例如：同一交换机在项目甲有10件、项目乙有5件，项目甲出库只能使用项目甲对应范围内的库存。

### 3. 扫码入库与出库

- 提供统一扫码作业入口，区分入库和出库模式。
- 支持USB扫码枪、手机浏览器摄像头及手动输入。
- 支持设备编码/IPN、原生物料码 `INV-PA#`、库存项码 `INV-SI#`、库位码 `INV-SL#` 及已绑定的外部条码。
- 可设置每次扫码数量，支持正数及最多5位小数。
- 入库支持备注，出库支持用途及备注。
- 扫到未知设备时可补充资料；审批模式下，审批通过后才正式建档和入库。
- 同一范围存在多个可能匹配的库存项时，要求明确选择，避免系统猜测应操作哪条库存。
- 切换方向或库位时处理已有草稿，降低连续扫码误操作风险。

### 4. 申请与整单审批

- 连续多次扫码可以组成一张申请单。
- 支持草稿、提交审批、通过、驳回、撤销、移除草稿明细和自动超时。
- 操作员可以查看“我的申请”，审批人员可以查看“待我审批”。
- 每个库位可配置审批负责人，负责人可以是用户或用户组；子库位可向父级寻找有效负责人。
- 申请人不能审批自己的申请，审批人员需具备相应权限。
- 审批通过时整单执行；任何一行校验失败，整单不部分落账。
- 保存申请人、审批人、时间、库位和处理意见等审计信息。

审批开关可配置。关闭时，符合条件的扫码直接增减库存；开启时，按申请审批流程处理。

### 5. 出库冻结与数量口径

出库扫码被接受后，先冻结对应可用库存，审批通过后才正式扣减实物库存。驳回、撤销、超时或移除相应草稿明细后释放冻结。

系统区分三种数量：

| 数量 | 含义 |
| --- | --- |
| 实物库存 | 当前账面上实际持有的数量 |
| 扫码冻结 | 已被扫码出库申请占住、尚未正式扣减的数量 |
| 可用库存 | 扣除原生业务占用和扫码冻结后，还能使用的数量 |

**可用库存＝实物库存－原生业务占用－扫码审批冻结。**

例如实物10件，销售订单占用2件，扫码申请冻结3件，可用库存为5件。库存移动、盘点、销售发货和生产领料等相关原生流程也接入了冻结保护，避免绕过审批使用已冻结库存。

### 6. 原生库存页面增强

- 保留原生库存页面、地点树、表格、列设置、分页和行操作。
- 使用原有搜索框查询设备ID、名称、项目、品牌、型号等内容。
- 增加项目、分类、地点、冻结状态等筛选。
- 支持库存明细与按设备汇总。
- 显示全部匹配结果的数量小计，不只统计当前页。
- 不同单位分别统计，不把不同单位的数量混加。
- 支持查看最后库存变动时间，以及导出全部筛选结果。
- 设备资料、期间记录和导入等工具接入原生页面，按需打开。

### 7. 设备资料与库存盘点导入

- 支持CSV和XLSX文件及模板下载。
- 上传后先预览，逐行校验资料、权限、匹配关系和数量差额。
- 确认后整批提交，失败时不留下部分成功数据。
- 支持设备资料导入、库存初始化和库存盘点。
- 盘点填写绝对数量，不是增加或减少的差额。
- 对冻结库存、匹配歧义、过期预览和重复提交进行保护。
- 保留导入任务审计记录。

例如原库存为10，盘点文件填写8，表示调整后应为8，预览差额为-2。同一设备、项目和实际地点匹配到多条原生库存项时，导入会拒绝歧义数据，不自动选择其中一条。

### 8. 期间记录与操作审计

- 按正式落账时间查询成功入出库，日期范围按中国时区处理。
- 统计成功记录数、设备种类数，以及分单位、分设备数量。
- 记录用途、备注、操作员、申请单、审批结果及失败原因。
- 保存库存变化前后数量，并关联原生库存流水。
- 保存人员及业务快照，便于后续追溯。
- 支持筛选、分页、详情和导出；多次扫码可聚合展示并展开明细。
- 普通日志查看者看到脱敏条码，管理员可按权限查看原始值。

盘点调整与扫码入出库是不同业务，不计入成功扫码入出库统计。

### 9. 项目候选与零库存提示

- 页面、筛选及导入导出表头统一使用“项目”。
- 仅输入项目名称而未成功保存，不会产生项目候选。
- 成功入库或初始化导入后，项目名称可以出现在候选中。
- 按设备、项目、实际库位查询实物量、冻结量、业务占用及可用量。
- 区分查询中、无法识别、查询失败、无库存和无可用库存。
- 没有库存或没有可用量时，禁止出库。
- 成功出库后重新查询余额，归零提示不覆盖已成功的操作记录。
- 待审批冻结不显示为正式出库成功。
- 页面定期及重新获得焦点时刷新，也支持手动查询；其他会话的审批结果不是即时推送。

### 10. 商品二维码标签与打印改进

- 增加商品IPN二维码标签，打印公司名称、商品名称和IPN。
- 二维码内容为纯IPN，代表商品，不是某一条库存项。
- 原生物料和库存项均提供打印入口。
- 缺少IPN时禁止生成此标签；支持多份打印，并限制单次总数量。
- 9月9日后续记录优化了50×30 mm标签排版，改善长编码和公司名称显示。
- 表格增加总选择数量、当前页外选择数量和清空选择，避免跨页打印时遗漏已选记录。

早期功能清单记载的是60×40 mm标签；后续记录针对50×30 mm模板进行了调整，实际打印尺寸需以使用环境的模板为准。

### 11. 企业微信通知

- 已实现直接入库成功及申请提交、通过、驳回、撤销、超时等通知。
- 支持按配置提醒审批人员。
- 通知在数据库事务提交后异步发送，发送失败不会回滚库存或审批结果。
- 需配置企业微信群机器人Webhook才会实际发送。

早期功能盘点记录显示Webhook尚未配置。本文未重新核验当前部署环境的通知配置，不能据此认定通知已经启用。

### 12. 库存安全、权限与部署支持

- 继续复用原生库存余额和库存调整方法，没有另建第二套库存账。
- 每次扫码使用唯一事件标识，网络重试不会重复增减库存。
- 对并发扣减、编码冲突和重复建档增加保护。
- 接入原生登录、库存权限、专用审批权限和审计权限。
- 导入及接口写操作也校验权限，不能仅通过绕过页面直接修改数据。
- 提供定制镜像、Docker Compose、后台任务、持久化及备份支持。
- 提供局域网HTTPS配置，满足浏览器摄像头扫码的安全上下文要求。

## 四、日常业务流程示例

### 入库

1. 选择目标库位及项目。
2. 扫描设备码，输入数量和备注。
3. 未知设备按要求补充资料。
4. 未开启审批时直接入库；开启审批时先生成申请并提交。
5. 审批通过后正式增加库存，记录操作及审批信息。

### 出库

1. 选择来源库位及项目。
2. 扫描设备码，检查可用库存。
3. 输入数量、用途和备注。
4. 审批模式下先冻结库存，再提交申请。
5. 审批通过后扣减库存；驳回、撤销或超时则释放冻结。

### 查库存与盘点

1. 按设备、项目和地点搜索库存，选择直属或包含下级范围。
2. 查看明细、汇总、实物量、冻结量和可用量。
3. 下载模板或导出适合回导的唯一匹配记录，填写实际盘点数量。
4. 上传文件，查看错误及差额，核对后整批提交。
5. 在库存流水和导入任务中追查调整结果。

## 五、当前功能边界

| 项目 | 当前边界 |
| --- | --- |
| 复杂审批 | 当前是一张申请对应一个审批Owner，不支持多级审批、会签或按金额动态路由 |
| 自动订单 | 扫码入出库不会自动生成采购订单、销售订单或正式发货单 |
| 序列号扫码增减 | 当前二开不支持序列号库存直接扫码增减，应使用相应原生业务流程 |
| 项目管理 | 项目用于库存归属，不包含项目预算、进度、合同等管理 |
| 外部系统同步 | 未实现正式ERP、MES或财务系统同步 |
| 离线扫码 | 未实现断网本地排队和恢复联网后同步 |
| 手机应用 | 本次二开提供浏览器扫码，未开发专用原生手机App；InvenTree上游另有配套App，不代表已适配本次二开流程 |
| 企业微信审批 | 当前是群机器人通知，不是企业微信应用审批或通讯录集成 |
| 商品与库存项码 | 商品IPN标签不能替代特定库存项的 `INV-SI#` 标签，两者含义不同 |

## 六、验收与部署状态说明

文档记录了基础库存、原生页面增量、项目与零库存提示、标签打印等专项验收。9月9日项目与零库存验收记录包含57项后端专项测试和11项前端单元测试通过，以及相关浏览器验证。

这些是历史验收记录，不是本次重新执行的测试，也不代表运行过整个InvenTree仓库的所有测试。部分后续变更明确只更新独立预览实例，因此“源码已有”“预览已验收”和“所有部署环境已更新”需要分别判断。
